## Critical methodology: independent expected bytes

The next experiment MUST establish the expected content independently before either checked method is called.

- Generate or define a deterministic small fixture from a source under test control.
- Preserve the original bytes independently of GitHub read methods, for example as locally generated bytes and a separately calculated byte count, character count, content digest, and Git blob SHA.
- Compute the expected Git blob SHA independently from the original bytes using Git's blob hashing rule: SHA-1 of `"blob " + decimal_byte_length + NUL + raw_bytes`.
- Record the fixture bytes/content, encoding, byte length, character count, digest/blob SHA, path, and immutable commit SHA before calling `fetch_file` or `fetch_blob`.
- Only then call each read method independently and compare each result directly to the pre-established fixture oracle. Never use one method's output as the oracle for the other.
- Distinguish byte equality, character count, encoding/normalization, and transport/API errors. Use `INCONCLUSIVE` when the oracle or read result cannot be established; do not relabel transport failure as a read failure.
- Keep the fixture isolated from canonical `main` and avoid changing unrelated state.
