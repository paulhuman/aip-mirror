# Документация AI-инфраструктуры

Каталог `.ai/docs/` содержит поддерживаемую документацию AI-инфраструктуры: архитектурный контекст, результаты исследований, практические пояснения и проектные предложения. Эти материалы помогают понимать и обслуживать инфраструктуру, но сами по себе не заменяют canonical semantic owners в skills, INDEX и других операционных подсистемах.

## Язык новых документов

**Новые документы в `.ai/docs/` пишутся на русском языке; необходимые технические термины, названия технологий, идентификаторы, пути, имена полей и точные технические обозначения сохраняются в оригинальном написании.** Точные цитаты и фрагменты внешних спецификаций не следует переводить так, чтобы терялась их проверяемость.

## Текущие документы

- `ai-document-hierarchy-and-authoring.md` — принципы иерархии документов, ownership, self-containment и авторинга.
- `agentic-ai-dsh-observations.md` — наблюдения о DSH; технические выводы требуют подтверждения для актуальной версии среды.
- `agentic-ai-skill-discovery-verification.md` — рабочая запись проверок skill discovery в DSH; содержит подтверждённые наблюдения и открытые вопросы.
- `ai-infrastructure-context-mode.md` — архитектурный контекст и границы активной инфраструктуры и архива; исторические разделы описывают состояние на момент проверки.
- `ai-infrastructure-vnext-proposal.md` — предложение по multi-host архитектуре. Это design proposal, а не автоматически принятое решение.
- `adapting-to-a-new-project.md` — практическое руководство по адаптации инфраструктуры к другому проекту.
- `manual-activation.md` — примеры ручного запроса ACTIVATE и TRACE.

## Организация и границы

Сейчас документы размещаются непосредственно в корне `.ai/docs/`, без вложенных тематических каталогов. README и ссылки должны отражать фактическую структуру репозитория.

Документы здесь — supporting/contextual material. Если документ описывает поведение, которое должно обязательно выполняться, его нормативная семантика должна находиться у соответствующего canonical owner. Документация может объяснять owner, сохранять rationale, показывать примеры или фиксировать evidence, но не создавать скрытую обязательную зависимость.

## Жизненный цикл

- Поддерживайте здесь документацию, которая остаётся полезной для текущей инфраструктуры, продолжающегося проектирования или воспроизводимой технической ориентации.
- Завершённые, замещённые или утратившие практическую актуальность исследования можно переносить в плоский архив `.ai/archives/memory/`, если они сохраняют историческую ценность.
- Незавершённые задачи и открытые вопросы, требующие рабочего сопровождения, хранятся в плоском `.ai/memory/`.
- Не архивируйте незавершённую работу только потому, что она устарела по путям или описывает прошлое состояние: сначала определите, остаётся ли она необходимым evidence для текущего proposal или исследования.

При обычной работе не нужно читать все документы целиком. Сначала определите нужный owner и вопрос, затем читайте только относящиеся к нему supporting docs.
