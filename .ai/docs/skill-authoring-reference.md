# Оформление SKILL.md: поля front matter и синтаксис

**Статус:** справочник с проверенными примерами
**Область:** формат `SKILL.md` и front matter для DSH Harness `0.2.0-rc.2`
**Тип:** поддерживающая документация; не является semantic owner

Этот документ описывает **синтаксис** оформления skill: какие поля front matter
существуют, какие значения принимают и что из этого реально влияет на поведение
DSH. Он нужен как справочник при написании новых skills.

Правила о том, **что** должно лежать в skill и кому принадлежит семантика,
остаются за `.ai/README.md`, `.ai/AGENTS.md` и `.ai/INDEX.md`. Здесь только
формат.

## Окружение проверки

| Параметр | Значение |
|---|---|
| DSH Desktop | 0.11.0 |
| Harness (`@deepseek-ai/dsh`) | 0.2.0-rc.2 |
| Источник фактов | реализация `dsh-skill-filesystem`, `dsh-skill`, `dsh-tool-skill` |
| Проверка | воспроизводимые пробы в живой сессии + записи `harness.log` |

Все утверждения ниже подтверждены запуском, а не чтением документации. Пробы
создавались как реальные skills, наблюдались в живом каталоге и в логе, затем
удалялись.

## Общая картина

Skill — это либо каталог с файлом `SKILL.md`, либо одиночный `.md` в корне
сканируемого каталога:

```
<корень>/skills/
├── my-skill/
│   └── SKILL.md          ← форма 1: каталог + SKILL.md
└── flat-skill.md         ← форма 2: одиночный файл
```

Обе формы проверены и работают. Третьего не дано: каталог без `SKILL.md`
игнорируется, файл без расширения `.md` игнорируется.

Вложенность **не сканируется**: skill внутри другого skill невидим. Глубина —
ровно один уровень.

```
front matter (YAML между ---)
        ↓
валидация: name + description обязательны
        ↓
разбор invocation-полей
        ↓
skill попадает в реестр
        ↓
фильтр isModelInvocable → каталог, который видит модель
```

## Полный список полей

DSH читает **ровно шесть** сущностей из front matter. Всё остальное молча
игнорируется.

| Поле | Обяз. | Тип | Влияет на |
|---|---|---|---|
| `name` | **да** | строка по шаблону | идентификацию skill, загрузку по имени |
| `description` | **да** | непустая строка | единственный текст о skill, который видит модель |
| `whenToUse` | нет | строка | **ничего** видимого (см. раздел) |
| `disable-model-invocation` | нет | boolean | скрытие от модели: каталог **и** tool-загрузка |
| `user-invocable` | нет | boolean | только инъекцию по явному упоминанию |
| `metadata` | нет | объект (mapping) | ничего видимого; переносится в объект skill |

> **Важно:** шестёрка — это исчерпывающий список. Ключи вроде `license`,
> `allowed-tools`, `version`, `author` **не являются полями DSH** и не дают
> никакого эффекта. Проверено: skill с `license`, `allowed-tools` и `metadata`
> загрузился нормально, лишние ключи не помешали и ни на что не повлияли.

## 1. `name` — обязательное

### Синтаксис

```yaml
name: my-skill-name
```

Шаблон: `/^[a-z0-9]+(?:-[a-z0-9]+)*$/` — только строчные латинские буквы, цифры
и одиночные дефисы между группами.

### Значения

| Значение | Результат |
|---|---|
| `my-skill` | принято |
| `skill2` | принято |
| `a-b-c-d` | принято |
| `My-Skill` | **отклонено** (заглавные) |
| `my_skill` | **отклонено** (подчёркивание) |
| `my skill` | **отклонено** (пробел) |
| `-leading` | **отклонено** (дефис в начале) |
| `trailing-` | **отклонено** (дефис в конце) |

### Имя каталога не обязано совпадать с `name`

Проверено экспериментально: каталог назывался `zz-folder-mismatch`, а
`name: zz-different-name`. Skill **загрузился**, и в каталоге появилось именно
`zz-different-name`.

Это значит: discovery идёт по каталогу, а идентификатор берётся из front matter.
На практике всё же лучше держать их совпадающими — иначе путь к файлу и имя
skill расходятся, и это путает при чтении дерева.

## 2. `description` — обязательное

### Синтаксис

```yaml
description: Что делает skill и когда его применять.
```

Требуется непустая строка. Это **единственный** текст о skill, который видит
модель, поэтому в него нужно укладывать и суть, и условие применения.

### Как текст попадает в каталог

Проверено по реализации:

```
1. все пробельные последовательности → один пробел
2. обрезка краёв
3. если длина > 500 → обрезать до 497 и добавить "..."
```

Лимит `500` — значение по умолчанию (`catalogDescriptionMaxLength`). Длинные
описания обрезаются в каталоге, но полный текст остаётся в front matter.

> **Частая ошибка:** двоеточие с пробелом внутри описания без кавычек. YAML
> воспринимает `: ` как начало вложенного отображения. Проверено — skill
> игнорируется с записью:
>
> ```
> ignored: invalid YAML frontmatter: YAMLParseError:
> Nested mappings are not allowed in compact mappings at line 2, column 14
> ```
>
> Лечится кавычками: `description: "Use when this: has a colon"`.

## 3. `whenToUse` — принимается, но модели не показывается

### Синтаксис

```yaml
whenToUse: Отдельная подсказка о том, когда применять skill.
```

### Что делает

Ничего видимого. Поле читается, проверяется на строку и переносится в объект
skill, но **не выводится** ни в каталог, ни в результат загрузки skill.

Проверено: маркер в поле не появился ни в каталоге, ни в теле загруженного
skill. Ошибок при этом нет — поле принимается молча.

> **Важно, чтобы не спутать.** Поле `whenToUse` **активно используется** в
> другом механизме — схеме workflow (`WorkflowMeta` в `dsh-tool-workflow`).
> Там оно работает. Речь здесь только о front matter skill.

**Практический вывод:** условие применения skill пишется в `description`.
`whenToUse` можно указывать для совместимости, но полагаться на него как на
механизм выбора skill нельзя.

## 4. `disable-model-invocation` — скрытие от модели

### Синтаксис

```yaml
disable-model-invocation: true
```

### Значения

| Значение | Эффект |
|---|---|
| поле отсутствует | skill **виден** модели (по умолчанию) |
| `false` | виден |
| `true` | **скрыт**: нет в каталоге, загрузка через tool заблокирована |

Проверено: skill с `true` отсутствовал в каталоге, а прямой вызов вернул

```
skill "zz-probe-modeloff" is not available for model invocation
```

Это единственное поле, которое убирает skill из поля зрения модели
**полностью** — и из каталога, и из возможности загрузки.

**Где применять:** для skills, которые вызываются только явной командой
пользователя и не должны предлагаться модели самостоятельно.

## 5. `user-invocable` — про другой путь

### Синтаксис

```yaml
user-invocable: false
```

### Значения

| Значение | Эффект |
|---|---|
| поле отсутствует | user-invocable (по умолчанию) |
| `true` | user-invocable |
| `false` | пропускается инъекция по явному упоминанию |

Проверено: skill с `user-invocable: false` **остался в каталоге** и успешно
загрузился. Поле влияет только на ветку, где DSH подставляет содержимое skill,
когда пользователь называет его в сообщении.

> **Частая ошибка:** использовать `user-invocable: false`, чтобы скрыть skill
> от модели. Так не работает — для этого нужен `disable-model-invocation`.

Различие двух путей:

```
isModelInvocable  → каталог + загрузка через skill tool
isUserInvocable   → инъекция по явному упоминанию в сообщении
```

Это **независимые** фильтры. Можно скрыть от модели, оставаясь user-invocable,
и наоборот.

## 6. `metadata` — свободный объект

### Синтаксис

```yaml
metadata:
  author: team
  version: 1.2.3
```

Требование — значение должно быть объектом (mapping), не массивом и не
скаляром. Переносится в объект skill, но **не показывается модели**.

Годится как место для собственных сведений, которые не должны влиять на
поведение: авторство, версия, ссылки на источники.

## Boolean-значения: принимаемые формы

Оба invocation-поля разбираются одной функцией, которая принимает больше форм,
чем просто `true`/`false`:

| Форма | Результат |
|---|---|
| `true` / `false` (boolean) | как есть |
| `1` / `0` (число) | `true` / `false` |
| `"1"` / `"0"` (строка) | `true` / `false` |
| `"true"` / `"false"` | `true` / `false` |
| `"yes"` / `"no"` | `true` / `false` |
| `"on"` / `"off"` | `true` / `false` |
| регистр строки | не важен (`TRUE`, `Yes` — то же) |
| любое другое значение | `TypeError`, skill игнорируется |

Проверено runtime: `"no"` → skill остался виден, `"yes"` → skill скрыт.

Несмотря на гибкость, **пишите `true`/`false`**. Остальные формы существуют ради
совместимости, а не как рекомендуемый стиль.

## Запрещённые имена полей

DSH **отвергает** camelCase-варианты явно, и это не предупреждение, а полное
исключение skill:

| Нельзя | Нужно |
|---|---|
| `disableModelInvocation` | `disable-model-invocation` |
| `modelInvocable` | `disable-model-invocation` |
| `userInvocable` | `user-invocable` |

Проверено, запись в `harness.log`:

```
skill file ...\SKILL.md ignored: invalid invocation frontmatter:
Error: frontmatter field "disableModelInvocation" is unsupported;
use "disable-model-invocation"
```

> **Важно:** единственный след такой опечатки — строка в
> `%APPDATA%\dsh-desktop\logs\harness.log`. В интерфейсе skill просто исчезает.

## Полные примеры

### Пример 1. Минимальный skill

Только обязательные поля. Такой skill виден модели и загружается.

```yaml
---
name: minimal-example
description: Показывает минимально допустимое оформление skill. Use when you need the smallest valid SKILL.md.
---

# Minimal example

Тело skill. Здесь обычный Markdown.
```

### Пример 2. С `whenToUse` и `metadata`

Оба поля допустимы, оба не видны модели. `description` несёт условие применения.

```yaml
---
name: with-optional-fields
description: Показывает допустимые необязательные поля. Use when you need an example that carries extra metadata.
whenToUse: Необязательная подсказка; в проверенной версии DSH модели не показывается.
metadata:
  author: aip-mirror
  reviewed: 2026-10-11
---

# With optional fields

Тело skill.
```

### Пример 3. Скрытый от модели skill

Не попадает в каталог, загрузка через tool заблокирована. Вызывается только
явной командой.

```yaml
---
name: hidden-from-model
description: Hidden from the model on purpose. Invoked only by an explicit user command.
disable-model-invocation: true
---

# Hidden from model

Этот skill не предлагается модели и не может быть загружен через skill tool.
Он предназначен для явного вызова пользователем.
```

### Пример 4. Скрытый только от инъекции по упоминанию

Остаётся в каталоге и загружается, но не подставляется автоматически, когда
пользователь называет его в сообщении.

```yaml
---
name: no-auto-injection
description: Stays visible to the model, but is not auto-injected on mention.
user-invocable: false
---

# No auto-injection

Skill виден модели и загружается через tool, но не подставляется автоматически
по упоминанию.
```

### Пример 5. Плоский файл вместо каталога

Файл лежит прямо в корне сканируемого каталога, без своей папки.

```yaml
---
name: flat-form
description: A single markdown file in the skills root, without its own directory.
---

# Flat form

Тело skill. Отдельного каталога для этого skill нет.
```

### Пример 6. Описание с двоеточием

Кавычки обязательны, иначе YAML ломается и skill исчезает.

```yaml
---
name: colon-in-description
description: "Важно: двоеточие с пробелом требует кавычек, иначе YAML не парсится."
---

# Colon in description

Описание взято в двойные кавычки.
```

## Что приводит к исчезновению skill

Все случаи проверены; в правой колонке — фактический текст из `harness.log`.

| Ошибка | Сообщение в логе |
|---|---|
| нет front matter | `ignored: missing YAML frontmatter` |
| YAML не парсится | `ignored: invalid YAML frontmatter: YAMLParseError: ...` |
| нет `name` или `description` | `ignored: frontmatter requires name and description` |
| `name` не по шаблону | `ignored: invalid skill name "ZZ_Bad_Name"` |
| camelCase-поле invocation | `ignored: invalid invocation frontmatter: ...` |
| boolean-поле с мусором | `ignored: invalid invocation frontmatter: ...` |
| каталог без `SKILL.md` | (молча пропускается) |
| вложенный skill | (молча пропускается) |

Общее свойство: **skill исчезает молча**. Ни диалог, ни каталог об ошибке не
сообщают. Единственное место, где видно причину, — `harness.log`.

## Шаблон для копирования

```yaml
---
name: my-skill
description: Что делает и когда применять — от этого зависит выбор skill моделью.
---

# My skill

Кратко: зачем этот skill существует.

## Когда применять

## Процедура

## Границы
```

Добавляйте поля только по необходимости:

- `disable-model-invocation: true` — если skill не должен предлагаться модели;
- `user-invocable: false` — если не нужна автоподстановка по упоминанию;
- `metadata:` — для собственных сведений.

## Как проверить результат

Посмотреть, что записал DSH, если skill не появился:

```powershell
Select-String -Path "$env:APPDATA\dsh-desktop\logs\harness.log" `
    -Pattern 'skill file|invalid skill name|requires name'
```

Проверить синтаксис `name` вручную:

```powershell
'my-skill' -match '^[a-z0-9]+(?:-[a-z0-9]+)*$'
```

Проверить, что YAML парсится, до коммита:

```powershell
node -e "const y=require('yaml');const fs=require('fs');const s=fs.readFileSync(process.argv[1],'utf8');const m=s.match(/^---\r?\n([\s\S]*?)\r?\n---/);console.log(y.parse(m[1]))" .ai/skills/my-skill/SKILL.md
```

Каталог обновляется без перезапуска: созданный или удалённый skill появляется и
исчезает в текущей сессии.

## Что осталось непроверенным

1. **Поведение на других хостах.** Всё выше проверено для DSH. Используют ли
   другие агентские хосты те же имена полей и ту же семантику — не проверялось.
2. **Задержка обновления каталога.** Наблюдалось, что каталог обновляется
   живьём, но точный интервал между изменением файла и обновлением не измерялся.
3. **Полное влияние `whenToUse`.** Потребитель не найден в установленных
   пакетах, но нельзя исключить использование сторонним клиентом.
